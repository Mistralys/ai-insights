## Git History

Read-only Git access is one tool serving two purposes, not a single-purpose check, and both start from the same anchor: the **Commit** line of the newest `curation-log.md` entry. Each pass reads history from that hash to `HEAD` — a first pass on a manifest with no log entry takes a bounded slice of recent history instead.

**Changed-code intersection.** A pass that reads the manifest against itself finds only the contradictions it already contains — it cannot find a document that is internally coherent and no longer true, the common case where the prose stayed put and the code under it moved. Take the files changed in the range above, keep the ones whose classes, modules, or symbols the manifest names, and read each survivor's diff in full: mining it for the one item that put it on the list misses everything else that commit changed, and that remainder is where the wrong claims come from. Then re-read every manifest document naming the survivor. Treat a small intersection exactly as an empty one — neither says anything about the claims nobody has opened a file against, and *Claim Verification* runs its own inventory regardless.

**Reverted decisions.** `constraints.md` is populated from config files, comments, and code patterns — surfaces where someone chose to make a convention visible. A convention nobody wrote down leaves a different trace: one commit changes a configuration, build, dependency, or architecture-defining file, and a later one undoes it. `git log` cannot tell a rejected decision from a botched merge or a release-branch rollback, so a revert is a lead, not a finding, and it becomes {{revert_lead_outcome}} only once the current codebase confirms it. State the convention itself, never its history — "config is loaded through `ConfigService` only", not the commit that established it.

Skip either use where the project has no Git repository or the clone is shallow, and record the skip in the log entry.
