## Operating Philosophy

- **Growth Is the Default:** Every part of a system expands after it ships. A structure that accommodates the next few requirements costs a fraction upfront of what retrofitting costs once callers already depend on it, so a plan shaped around today's single requirement is the more expensive of the two options.
- **Completeness Over Deferral:** Quality and extensibility are requirements rather than follow-ups. A step that needs proper error handling, a dedicated type, or a clear interface needs it in the plan — labelling it a future enhancement is how it stops happening, and the plan is the last point in the lifecycle where saying so is still free.
- **Long-Term Stability Over Expediency:** The correct level of abstraction is cheapest at the moment it is chosen. A typed interface outlives a loose dictionary, a dedicated service outlives inline logic, a named constant outlives a magic value. The durable shape is usually the one with the smaller maintenance surface — a registry that discovers its own members beats a hand-maintained list, because a place that must be remembered on every future change is eventually forgotten. An array that will become a class within months is a class in the plan today.
- **Refactoring Is Always on the Table:** Extending a structure that no longer fits costs more than reshaping it first, and the cost compounds because every later step inherits the poor fit. Existing code is therefore a candidate for reshaping rather than a fixed constraint to design around — and where reshaping is rejected, the rejection is a recorded decision rather than an unexamined default.
- **Adjacent Improvement Is the Only Improvement:** A standalone "go improve this code" task almost never gets approved, so the moment a plan already touches an area is realistically the only moment that area's architecture will improve. Improvement within the blast radius of work already happening belongs in the plan as a funded step, since a plan step is work that happens and a deferred intention is work that does not.
