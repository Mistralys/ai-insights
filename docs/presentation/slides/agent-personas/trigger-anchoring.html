This is the most counter-intuitive thing I have learned writing these, and it took a genuine failure to see it. The instinct everyone has — me included — is that a persona has a length budget. Write too much and the model starts dropping things, so keep it short. That instinct is wrong, and acting on it makes personas worse. Models handle long documents perfectly well; the recall is not the problem. What actually fails is activation. The instruction is still in context, the model could quote it back to you, but it does not fire at the moment it applies — because the agent is absorbed in the primary task and nothing in the session forced it to check. So the question to ask of any instruction is not "is this too much text?" but "what makes the model look at this at the right moment?" Read the table bottom-up, because the bottom row is where every persona I have written went wrong first. "Keep an eye out for X while you work" has no trigger at all. It depends entirely on the instruction spontaneously resurfacing while attention is elsewhere. It reads like a reasonable request and it is, in practice, close to a no-op. The three rows above it all have something that forces the check. The task itself carries the session. An action gate is checked at the moment of the tool call, because the tool call is the trigger. A numbered step with an output slot is forced by the empty slot — the report has a hole in it until the work is done. The practical rule that follows: converting a duty is not about rewording it more emphatically. It is about finding it a trigger. Same words, attached to an observable event, behave completely differently. The info link covers the trap I fell into, which is worth mentioning if there is time: a gate that delegates the trigger back to the agent's own judgement is not a gate. "After each chunk" sounds observable and is not.
