### Outcome Summary

All seven verified Copilot findings on PR #64 are fixed, together with the fail-open pattern behind three of them. A new shared read primitive now separates a missing state file from a corrupt or unreadable one, and each store applies its own policy: the counter file fails closed into the existing temporary-code fallback, the temporary-code log recovers after keeping a copy, and the config falls back field by field. The plan was revised mid-session for a local, single-user tool that routinely runs parallel workflows, so the per-user lock was kept (no cross-user lock) and concurrency is proven by in-process and cross-process tests.

### Implementation Summary
- **F1:** `peek` on the Errorcode Incrementor deletes any `increment` parameter already in `base_url`; `allocate` still sets exactly one. The provider owns `pw`, `counter` and `increment`.
- **F2/F3 (file provider):** the counter file is read strictly inside the lock. Only a missing file starts a sequence; a corrupt or unreadable one returns a non-ambiguous `failed` outcome and is never overwritten, so the allocator issues a temporary code. Counters live in a `Map`, so `__proto__`, `constructor` and similar names are ordinary keys.
- **F4:** decided by the user as single-user. The `data_dir` lock stays, since every process of one user shares it. The misleading `.lock` comment and the matching manifest note were corrected, and a counter file shared between users or machines is documented as unsupported.
- **F5 (temporary-code log):** a corrupt log is recovered under the lock: a byte-identical copy is kept, valid entries are retained, numbering continues above every counter still visible, and a `warning` is returned (surfaced as `ErrorCodeResult.warning`). Listing is read-only and returns `{ entries, warning? }`. An unreadable log fails closed.
- **F6 (GUI):** a visit token (`ecVisit`) guards the lazy load, Save and Test callbacks. A new `ecResetState()` replaces the copied reset lists in `config.js`. A failing temporary-codes fetch no longer blocks the settings form.
- **F7 (prefix and config):** the temporary prefix must be 1–6 digits with no leading zero, enforced in the persisted-config schema, the PUT body schema and the form. Config reads fall back per field, so an invalid stored prefix reads as `777` and every other field, including providers and secrets, is kept. A config update refuses to write over an unreadable file and keeps a copy of an unparsable one first.
- **Shared approach:** `src/storage/json-state-file.ts` (`readJsonStateFile`, `keepCorruptCopy`). Corrupt files are copied, never renamed, so unlocked readers in other processes never see a file missing.
- **Beyond the plan's wording:** a schema-valid log whose `next_counter` is missing or not above every logged code goes through the same recovery path (see Implementation Decisions).

### Code Insights

#### Implementation Decisions
- [MEDIUM] (decision) mcp-server/src/error-codes/temporary-codes.ts: Beyond the plan's wording, a schema-valid log whose `next_counter` is missing (the Zod default fills in 1) or not above every logged code is routed through the same recovery path. Without it such a log would pass validation and reissue `777000001`, which is exactly F5; the plan's test (d) requires it.
- [MEDIUM] (decision) mcp-server/src/error-codes/config-store.ts: Config warnings deliberately omit the JSON parser's message. Node's `SyntaxError` quotes a snippet of the file and `config.json` holds provider secrets. The counter-file warning keeps the parser message, since that file holds no secrets and the position helps a hand repair. Keep the message out of any caller of the shared helper that handles secrets.
- [LOW] (decision) mcp-server/src/error-codes/providers/file-provider.ts: Counter values are validated as safe integers ≥ 0 instead of any integer. A stored 0 or negative can only come from hand-editing and is treated as corrupt (fail closed).

#### Follow-Up Items
- [LOW] (debt) mcp-server/src/storage/atomic-writer.ts: `atomicWriteJson` names its temp file `{file}.tmp.{pid}`. Two concurrent unlocked writers in one process would share a temp path. Every current caller is locked, so it is latent; a random suffix would make the primitive safe on its own.
- [LOW] (code-smell) mcp-server/gui/public/views/config.js: `renderConfigPage` still hand-lists the reset fields of the Stores, Persona Models and Model Registry tabs, duplicated again in the tab-bar exit branch. Give each tab module its own reset function and visit token, as Error Codes now has.
- [LOW] (improvement) mcp-server/gui/api-error-codes.ts: `handleUpdateErrorCodeConfig` passes `fieldErrors` as `ApiError` details, but the GUI error serializer drops them, so a rejected PUT returns only "Invalid request body." (observed live). Surface the first field message in the 400 body.
- [LOW] (debt) mcp-server/tests/gui/api.test.ts: One full-suite run failed `handleGetProject … timing.total_active_ms` with `ENOTEMPTY` while removing its temp ledger directory, then passed alone and on re-run. Likely a teardown race under load; use `rm` with `maxRetries` in that test's cleanup.
- [LOW] (debt) mcp-server/tests/error-codes/temporary-codes.test.ts: The parallel-call tests take many seconds because each contested `withLock` acquisition backs off 200–1000 ms. Injectable lock options (test-only) would speed up every concurrency test without changing production defaults.
- [LOW] (improvement) mcp-server/tests/error-codes/fixtures/run-workers.ts: A small shared spawn helper was added beside the plan's worker script; a future store with a cross-process requirement can reuse it by adding a worker mode.
- [LOW] (improvement) mcp-server/gui/public/views/config.js: `renderConfigPage` now calls `ecResetState()`, which also runs `ecCleanup()` against the old content element before it is replaced. Harmless, but a small behaviour change worth knowing when debugging listener counts.
- [LOW] (improvement) mcp-server/src/error-codes/temporary-codes.ts: Recovery warnings are also written to stderr, so a recovery leaves a trace even when a caller ignores `ErrorCodeResult.warning`. Tests that exercise recovery emit that line.
- [LOW] (debt) mcp-server/docs/agents/project-manifest/api-surface.md: The error-code entries are dense single paragraphs with "WP-0xx" provenance tags; the new behaviour was added in the same style. Short bullet lists, as in the incrementor entry, would read better.
- [LOW] (convention) mcp-server/.context/mcp-server/manifest-constraints.md: The generated context output still carries the old lock-file heading and pre-fix error-code docs. Regenerate it with Build & Maintain when committing on the default branch.
