### Outcome Summary

The persona deploy targets moved to the global Copilot home. VS Code skills now publish to `~/.copilot/skills/`, and the global MCP registration is written to `~/.copilot/mcp-config.json` in the Copilot CLI schema, which VS Code also reads through its default-on Copilot CLI discovery. All Copilot locations honour `COPILOT_HOME`, and the installer function was renamed to `installCopilot()`.

### Implementation Summary
- `shared/publish-locations.json` gained the Copilot skills, MCP config and `copilot_home` entries; any location under the `copilot_home` prefix is rebased onto `COPILOT_HOME` when it is set (blank values ignored, Claude locations never rebased).
- `scripts/publish-locations.js` and `mcp-server/src/utils/publish-locations.ts` implement the rebasing; new helpers `getVSCodeSkillsDir()` and `getCopilotMcpConfigPath()`.
- `scripts/publish-skills.js` deploys the VS Code target to the Copilot skills directory instead of workspace `.github/skills/`.
- `scripts/install-mcp-global.js` writes `mcpServers` entries of `type: local` with all tools enabled, creates owner-only backups, and uninstall clears both the new file and the legacy VS Code user `mcp.json`. Install leaves the legacy entry in place.
- `installVSCode()` renamed to `installCopilot()` without an alias.
