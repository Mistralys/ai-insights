# Generated Artefacts

Which tracked files a build step writes at the workspace level, which command writes each, and when a modified copy can be discarded. This document covers the whole repository; the personas module's own [generated-artefacts.md](../../../personas/docs/agents/project-manifest/generated-artefacts.md) carries the detailed rows for persona-build output, and the two documents are meant to agree. The binding rules derived from this table are not yet written down in a hub `constraints.md`, because the hub has none; see the [Curation Log](curation-log.md) for the deferral.

## Purpose and Branch Policy

The owner's stated practice is the one the [Git Committer](../../../personas/standalone/src/content/git-committer.md) persona enforces, recorded as a Standing Decision in the [personas Curation Log](../../../personas/docs/agents/project-manifest/curation-log.md). That persona is the authority; this section summarises it. On a feature branch, generator drift is not committed. A file whose row's *Safe to discard when* condition holds stays out of the commit and is discarded by path before an upstream integration. A file whose source the branch changed is committed with that source change. `.context/**` counts as drift on every feature branch whatever its row says, so CTX output enters version control only on the default branch, as its own `CTX: Updated docs` commit. On any branch, a generated file whose diff is only a timestamp or date is not committed.

The repository itself enforces something narrower. The `.githooks/pre-commit` hook blocks a commit on a failing `node scripts/build-personas.js --check` or `node scripts/check-version-sync.js`, and on ruff for staged orchestrator Python. It only warns when presentation sources change without a rebuilt `docs/presentation/dist/`, and when staged source under `mcp-server/src/`, `orchestrator/src/`, `personas/`, `scripts/` or `shared/` carries no `.context/` change. It never compares generated files against disk.

## How to Read Tracked Status

`git ls-files <path>` decides whether a file is tracked. An entry in `.gitignore` proves nothing on its own, because a file committed before its ignore entry stays tracked.

## Tracked Generated Artefacts

### Runtime-coupled

Committed code reads these files, so a stale copy changes behaviour, not just documentation.

| Path / glob | Generated by | Source | Safe to discard when | Unsafe to discard when |
|---|---|---|---|---|
| `personas/name-mapping.json` | `node scripts/build-personas.js` (real builds only), also run by `node scripts/cli.js build-maintain`. | Persona YAML in all suites and the model registry; see the personas document for the full row. | The diff is limited to the `model`, `model_slug` and `cc_model` fields and the branch changed no model assignment — machine-local registry drift. | The branch changed a persona's naming fields, version or changelog, or added, renamed or removed a persona. The MCP server's agent names depend on it. |
| `docs/presentation/dist/ai-insights-slides.html` | `docs/presentation/build.sh` (or `build.cmd`), which runs `node tools/build.js`; `node tools/build.js --check` verifies it is current. | `docs/presentation/template.html`, `slides.json`, `slides/`, `partials/`, `img/` and `changelog.md`. | The branch changed none of those sources and the diff is only rebuild noise. | The branch changed any presentation source. The committed HTML is the distributed deliverable and is the first materialisation of that change. |

## Ignored Generated Artefacts

These are not tracked, so there is nothing to revert or commit.

| Path / glob | Regenerate with |
|---|---|
| `personas/{ledger,standalone,ledger-support}/{vs-code,claude-code,deep-agents}/*.md` — built persona files | `node scripts/build-personas.js` (deploy with `node scripts/sync-personas.js`) |
| `dist/*.zip` — packaged standalone personas | `node scripts/cli.js package-personas` |
| `dist/vscode-skills/`, `dist/claude-skills/` — built skills | `node scripts/build-skills.js` (deploy with `node scripts/publish-skills.js`) |
| `build/` — the NotebookLM bundle and the workflow specification bundle | `node scripts/cli.js bundle-docs` (`scripts/bundle-docs.js`) |
| `mcp-server/dist/` — compiled server | The MCP server's build script in `mcp-server/package.json` |
| `orchestrator/{checkpoints,logs}/`, `.orchestrator-run.json` — orchestrator run state | Written by orchestrator runs; not regenerable on demand |

## Hand-maintained Neighbours

Files that sit next to generated output or feed a generator, but are source. Never revert them as build noise.

| Path | Why it looks generated | Why it is source |
|---|---|---|
| `context.yaml`, `**/module-context.yaml` | Named like CTX output. | CTX input configuration, owned by the CTX Architect. |
| Root `AGENTS.md` and root `CLAUDE.md` | `.context/agents.md` is no longer generated, and the root `context.yaml` does not import `AGENTS.md`. `CLAUDE.md` was once generated from `AGENTS.md`. | Both are hand-maintained; `CLAUDE.md` holds an `@AGENTS.md` import and `ctx-generate` no longer writes it. |
| `docs/presentation/{template.html,slides.json,slides/,partials/,img/,tools/}` | Sit beside the generated `dist/`. | Presentation sources. |
| `docs/presentation/dist/` neighbours: `README.md`, `notes.md`, `docs/` | Live under the presentation folder. | Hand-written. |
| `scripts/templates/` | Feed generators. | Hand-written templates for the agents overview and bundles. |
| `personas/docs/audits/{notes.md,annotations.json}` | Beside the generated `status.md`. | Hand-written input of `generate-persona-audit.js`. |
| `personas/model-registry/default.json` | JSON beside machine-local registry state. | Shipped seed model list. |
| `docs/agents/project-manifest/**` and the module manifests | Imported wholesale into `.context/`. | The source `.context/` manifest copies derive from. |
| `skills/{meta,src}/` | Feed `build-skills.js`. | Skill sources. |

## Commands That Touch More Than They Generate

| Command | Writes beyond its generated output |
|---|---|
| `node scripts/cli.js ctx-generate` | Deletes `.context/` entirely before regenerating. Requires the `ctx` binary on `PATH`. This is the lighter docs-only command. |
| `node scripts/cli.js build-maintain` | The full build. Runs `mcp-server/scripts/sync-version.js`, synchronises the root `package.json` and `orchestrator/pyproject.toml` versions from their changelogs, builds all persona suites (rewriting `personas/package.json` `version` and `personas/name-mapping.json`), regenerates `docs/references/agents-overview.md`, runs `check-known-roles.js`, and finishes with `ctx-generate`. |
| `node scripts/sync-personas.js` | Runs the full build, then copies output outside the repository into the VS Code agents directory and `~/.claude/agents/`, and skills into `~/.claude/skills/`. |
| `node scripts/cli.js package-personas` | Unless `--skip-build` is given, first runs `build-personas.js --strict`, which builds every suite. |

## Known Contradictions

- **`personas/name-mapping.json` depends on untracked, machine-local files.** Its model fields resolve from gitignored `local.json` and `assignments.json`, so two machines building the same commit write different model fields. A diff confined to those fields is machine drift. A pending plan (`docs/agents/plans/2026-10-15-untrack-name-mapping/`) proposes untracking the file; until it lands the file is tracked and this row stands.
