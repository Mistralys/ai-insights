# Generated Artefacts

Which files under `mcp-server/` a build step writes, which command writes each, and when a modified copy can be discarded. This document covers the MCP server module only. Repository-wide rows (persona output, `name-mapping.json`, the presentation bundle, the agents overview) live in the hub's [generated-artefacts.md](../../../../docs/agents/project-manifest/generated-artefacts.md) and are not repeated here. The binding rules derived from the table are in the [Generated Artefacts section of constraints.md](constraints.md#generated-artefacts).

## Purpose and Branch Policy

The owner's stated practice, summarised in the hub document and enforced by the Git Committer persona, is that generated artefacts are not committed on feature branches. A file whose diff is generator drift is discarded by path; a file whose source the branch changed is committed with that change. `.context/**` is drift on every feature branch and enters version control only on the default branch.

## How to Read Tracked Status

`git ls-files <path>` decides whether a file is tracked. A `.gitignore` entry proves nothing on its own, because a file committed before its ignore entry stays tracked.

## Tracked Generated Artefacts

### Runtime-coupled

| Path / glob | Generated by | Source | Safe to discard when | Unsafe to discard when |
|---|---|---|---|---|
| `mcp-server/package.json` (`version` field only) | `npm run sync-version` (`scripts/sync-version.js`), run automatically by the `predev` hook and by the hub's `build-maintain`. | The top version header of `mcp-server/changelog.md`. | The diff is limited to the `version` field and `changelog.md` is unchanged by the branch (stale local value). | The branch edited `changelog.md`, or the diff touches anything beyond `version`: the rest of the file is hand-maintained. |

### Documentation-style

| Path / glob | Generated by | Source | Safe to discard when | Unsafe to discard when |
|---|---|---|---|---|
| `mcp-server/coverage/**` | `npm run test:coverage` in `mcp-server/` (`vitest run --coverage` with `@vitest/coverage-v8`). `vitest.config.ts` sets no `coverage` options, so Vitest's defaults apply: reporters `text`, `html`, `clover` and `json`, written to `coverage/` beside the config. That matches the tracked set (`index.html`, per-source `*.ts.html` pages, `clover.xml`, `coverage-final.json`, and the static assets). | `mcp-server/src/`, `mcp-server/gui/` and the tests that exercise them. | Always on a feature branch: any diff here is a regenerated report, and the tracked copy is a single historical snapshot that is not kept current. | Only if the user confirms the snapshot is meant to be maintained and the branch changed covered source. The report is not referenced by any build, hook or script, so nothing at runtime depends on it. |

## Ignored Generated Artefacts

| Path / glob | Regenerate with |
|---|---|
| `mcp-server/dist/` — compiled server (`tsc`, `outDir` `./dist`); ignored by the root `.gitignore` | `npm run build` in `mcp-server/` |
| `mcp-server/node_modules/` | `npm install` in `mcp-server/` |

The `.context/mcp-server/**` output for this module is tracked under the hub's `.context/**` row and follows that row's verdicts. It is written by the hub-level `node scripts/cli.js ctx-generate` from this module's `module-context.yaml`, never by an `mcp-server` npm script.

## Hand-maintained Neighbours

| Path | Why it looks generated | Why it is source |
|---|---|---|
| `mcp-server/module-context.yaml` | Named like CTX output. | CTX input configuration, owned by the CTX Architect. |
| `mcp-server/docs/agents/project-manifest/**` and `mcp-server/gui/docs/agents/project-manifest/**` | Imported wholesale into `.context/mcp-server/`. | The source the `.context/` copies derive from. |
| `mcp-server/package-lock.json` | Machine-written by npm. | Committed lockfile; changes with dependency edits, not with builds. |
| `mcp-server/storage/` | Holds runtime-looking data. | Per-project ledger runtime data layout; contents are governed by [constraints-storage.md](constraints-storage.md), not by a build. |

## Commands That Touch More Than They Generate

| Command | Writes beyond its generated output |
|---|---|
| `npm test` | The `pretest` hook runs `node ../scripts/build-personas.js` and then `--check`, so every test run rebuilds persona output and may rewrite the tracked `personas/name-mapping.json` (see the hub document for its verdicts). |
| `npm run dev` | The `predev` hook runs `sync-version`, which can rewrite `package.json`. |
| `npm run test:coverage` | Calls `vitest` directly, so the `pretest` hook does not run, and it rewrites the tracked `coverage/` tree. |

None known for this module.
